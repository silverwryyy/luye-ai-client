# AGENTS.md —— 路夜助手工作规范（根级）（Luye v1.1）

本文件管的是「路夜助手自身怎么干活」：工程铁律、踩坑记录、外部组件接入约定。

> **路径基准**：本文件里出现的相对路径，一律以**本包根目录**（即本 `AGENTS.md` 所在目录）为基准。
> 换机 / 换盘 / 拷包后自动跟随，无需手改。

## Hard-won Lessons

### L1. 长任务一律走 run_bg.py，禁止用 run_command 硬扛

- **症状**：下载 33.5MB 二进制时用 `run_command` 跑，超时后被掐断，进程句柄没释放，
  **整轮对话锁死**——既不能继续对话，也不能新开对话，只能重启进程。事后留下一个 0 字节空壳文件。
- **根因**：`run_command` 单次上限 300 秒；超时掐断不等于进程干净退出，句柄可能悬挂。
- **铁律**：
  1. 凡是**耗时可能超过 60 秒**的活儿（大文件下载 / 编译 / 长脚本 / 批量转换），
     一律用 `tools\run_bg.py` 后台启动，命令**秒回**。
  2. 之后用 `python run_bg.py status <名字>` 轮询，**每次都是秒级返回**，绝不阻塞。
  3. 判断「下载/安装完成」以 `.done` 标记 + 文件体积/哈希为准，别只看日志尾部。
  4. 前台只跑「确定短」的命令（扫目录、读文件、单条查询）。
- **命令速查**：
  ```
  python tools\run_bg.py start  <名字> -- <命令...>
  python tools\run_bg.py status <名字>
  python tools\run_bg.py tail   <名字> [行数]
  python tools\run_bg.py stop   <名字>
  ```
- **产物**：`logs\<名字>.log / .pid / .done`。

### L2. 大文件下载要「先探体积、再给足余量、后校验哈希」

- 下载前先探 `Content-Length`；下载后比对文件体积与官方 `SHA256SUMS`，
  0 字节或哈希不符一律视为**未完成**，删掉重来。

### L3. 依赖的产物只放本地固定盘，永不依赖可移动盘

- **症状**：把一批外部工具的 `.cmd` 包装放进外接盘（图它早已在 PATH 里、省一步改环境变量）。
  但那是移动硬盘——拔盘 / 换机 / 盘符漂移时包装**静默消失**，裸命令莫名失效，极难排障。
- **根因**：为省一步「新建目录 + 改 PATH」，牺牲了稳定性。
- **铁律**：任何**被依赖的可执行文件、包装脚本、工具目录**，一律放**本地固定盘（C:/D:）**；
  可移动盘只当临时中转，绝不作为 PATH 里的常驻来源。

### L4. 批处理（.cmd/.bat）的括号块：禁用裸 `%~1`，函数返回只写 `goto :eof`

- **症状**：`_auto_python.bat` 的 `:tryexe` 里把 `%~1` 直接写进 `if exist` 的括号块，
  探测「含空格路径」时**解析期就炸**，连自带的错误提示都来不及打；表现为
  「Python 明明装好了，却没接上」。
- **根因**：`%~1` 展开后自带引号，进括号块再叠一层引号，cmd 当场翻脸。
  更阴的是 cmd **遇错不崩、只静默走错分支**，表面上一路绿灯。
- **铁律**：
  1. 函数块内先落地 `set "CAND=%~1"`，之后一律用 `%CAND%`，**不再直接引用 `%~1`**。
  2. 所有路径变量一律 `set "X=..."` 加壳；**绝不裸写 `set X=C:\Program Files`**
     —— 空格截断后 `if exist` 静默判 false，脚本不报错、直接跑偏。
  3. 函数块内**只写 `goto :eof` 返回，绝不写 `exit /b`**（后者会连带退出整个脚本）。
  4. 每一步都要**显式查错并打印一行**，别拿「脚本没停」当成功。
- **验证方式**：改完必须造「含空格路径」「不存在的路径」两种夹具各跑一遍，确认不崩、判定正确。

### L5. 改文本文件前先探换行符，别按换行符硬拼多行锚点

- **症状**：给 `AGENTS.md` 打补丁时按 `\n` 拼多行锚点，文件其实是 **CRLF**，脚本直接 `ANCHOR NOT FOUND`。
- **根因**：Windows 仓库里的 `.md` / `.cmd` 多为 CRLF，按 `\n` 硬拼的锚点与真实行尾对不上。
- **铁律**：
  1. 改任何文本文件（`.md` / `.cmd` / `.py` / `.env` / `.txt`）前，**先探换行符**（行尾是 `CRLF` 还是 `LF`）。
  2. 打开时用 `newline=''` 或二进制读取，按行拆开处理；**锚点只取单行**，或先统一换行再匹配。
  3. 写入时**沿用原换行符与 BOM**（CRLF 就还 CRLF，有 BOM 就保留 BOM），别顺手改格式。
  4. 匹配失败的失败分支必须**一个字都不写**（`continue` / 提前返回），别半途把文件写坏。
  5. 两份副本（运行本体 + 母版）改完，用 `fc /b` **逐字节比对**确认一致。

### L6. 闪退先看证据，别靠猜（v1.1 崩溃遥测）

- **症状**：程序「突然就没了」，`error.log` 一个字节都没有，等于没有现场。
- **根因**：硬崩（Native 层 / 信号）根本不走 Python 的 `try/except`，异常钩子抓不到。
- **铁律**：排闪退按这个顺序看文件，不许跳步——
  1. `launch_trace.log`：启动阶段挂的，一步步看到哪行停；
  2. `runtime_heartbeat.txt`：最后一次刷新的时间戳 = 死亡时刻；
  3. `crash_trace.log`：faulthandler 挂在 SEH 上刷的各线程栈；
  4. `error.log` / `save_error.log`：有 Python 异常时才有。
- **心法**：「没有报错」不等于「没有证据」——先证明它死于几点几分、死在哪一步，再谈修。

## 外部组件：本包不带，需要请自装

路夜可以调用几类外部工具来干重活，但它们体积大、各自授权独立，**没有打进本包**。
想用就自己装好，放到 `tools\` 下对应目录，并在主程序的 `_RUN_ALLOW_FIRST` 白名单里
登记它的可执行名（否则每次调用都会弹确认框等你点「是」）。

| 组件 | 干什么 | 建议放哪 |
|---|---|---|
| **PPT Master** | 生成 PPTX | `ppt-master\` |
| **OfficeCLI** | docx / xlsx / pptx 细读、元素级写、OpenXML 校验、渲染自查 | `tools\officecli\` |
| **Skills 库** | TDD、code-review、diagnosing-bugs 等工程技能，供 `read_skill` 读取 | `skills\skills\` |

- **白名单同步铁律**：`run_command` 的白名单在主程序 `desktop_bug.py` 里的 `_RUN_ALLOW_FIRST`，
  按「每段的第一个命令名」判定（已剥离 `.exe/.bat/.cmd/.ps1/.py`）。
  **每次接入新库 / 新外部工具，必须同步把它的可执行名登记进去**，否则每条命令都要手动确认。
  改完要**重启路夜**才生效（白名单集合在模块加载时构建）。
- **三个组件都不装也能用**：对话、联网搜索、扫目录、读文件、写文件、读写 Word 全部照常。
- **许可证**：这些第三方组件各自遵循其原有许可证（如 MIT / Apache 2.0），
  使用前请自行阅读，并保留其 LICENSE 文件。

## 危险命令确认机制（本程序内建，与外部组件无关）

- `run_command` 对危险命令（删除、改名、改注册表、`git push` 等）以及**不在白名单里的命令**，
  一律弹确认框，**必须人工点「是」**才执行；没写 `why`（意图与目的）的会被直接打回。
- 硬黑名单（格式化、`diskpart`、写 `System32` 等）**直接拒绝，连问都不问**。
- 判定与白名单都在主程序 `desktop_bug.py` 里（`_RUN_DANGER` / `_RUN_DENY` / `_RUN_ALLOW_FIRST`）。
